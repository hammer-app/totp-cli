# 要件定義書: Custom CLI TOTP Authenticator (`totp-cli`)

## 1. 概要 (Overview)

特定端末および指定復号鍵が存在する場合のみ実行可能な、**「端末固定（クライアント認証）」および「ポータブル運用」を目的としたマルチプラットフォーム対応CLI型TOTP生成ツール**。

暗号化したTOTPシークレット群（JSON）と復号鍵（AES-256-GCM）を物理的に分離管理し、実行時にメモリ上で復号してワンタイムパスワードを出力する。

---

## 2. 目的・背景 (Background & Objectives)

* **目的:** 外部デバイスに依存せず、特定デバイス・特定鍵アクセス環境でのみ機能するセキュアなクライアント認証環境の構築。
* **背景:**
  * クラウド同期型パスワードマネージャーへの過度な依存を避け、端末上のターミナル環境で高速かつ安全に2FAコードを利用したい。
  * 鍵と暗号化ファイルを分離配置することで、Windows Personal Vault、外部メディア、Linux、macOS 等の異なる環境間でも安全に同一設定を引き継ぎたい。
  * Windows 環境特有のパス扱い（引用符混入や空白パス）でもクラッシュせず、パイプ連携が安全に行える堅牢な CLI を実現する。

---

## 3. 機能要件 (Functional Requirements)

### 3.1 核心機能

1. **TOTPコード生成・表示 (`generate` / `get` / `-g`)**
   * サービス名を受け取り、対応する 6 桁の TOTP コードを出力する。
   * **基本形:** `totp generate <service>` / `totp get <service>` / `totp -g <service>`
   * **省略形:** `totp <service>`
     * 第一引数が予約済みサブコマンドと一致しない場合は自動的に `generate` として処理する。
     * サブコマンドと同名のサービス名（例: `init`）を呼び出す場合は明示的にサブコマンド（`get` / `generate`）を付与する。

2. **鍵パスの動的指定・解決優先順位 (`-k` / `--key`)**
   * 復号鍵（`master.key`）の保存先は、以下の優先順位に従って決定する。
     1. コマンドライン引数 (`-k` / `--key PATH`)
     2. 環境変数 (`TOTP_KEY_PATH`)
     3. 設定ファイル (`~/.totp-cli/config.json` 内の `key_path`)

3. **暗号化ストレージの動的指定・解決優先順位 (`--storage`)**
   * 暗号化データファイル（JSON）の保存先は、以下の優先順位に従って決定する。
     1. コマンドライン引数 (`--storage PATH`)
     2. 設定ファイル (`~/.totp-cli/config.json` 内の `storage_path`)
     3. 既定パス (`config.json` と同一ディレクトリの `totp-secrets.enc`)

4. **複数サービス（マルチアカウント）管理**
   * 複数の TOTP シークレットを 1 つの暗号化ストレージで安全に保持・管理する。

### 3.2 ライフサイクル・データ管理機能

1. **初期化機能 (`init`)**
   * 新規の復号鍵（32バイト AES 鍵）を生成し、空の暗号化ストレージファイルと初期設定ファイルを作成する。
   * 鍵パスは引数（`-k` / `--key`）または対話プロンプトで取得する。
   * 既存の鍵が存在する場合は二段階の破壊的変更警告と確認プロンプトを挟む。
2. **鍵の更新・再暗号化機能 (`rekey`)**
   * 新しい復号鍵を再生成し、既存の暗号化データを旧鍵で復号した上で即座に新鍵で再暗号化して保存する。
   * 旧鍵は最大 3 世代まで `<key_path>.1` 〜 `<key_path>.3` として自動退避する。
3. **登録一覧表示 (`list` / `ls`)**
   * 登録済みのサービス名（Key）および発行者（Issuer）を表示する（シークレット自体は非表示）。
4. **登録データ追加・更新 (`add`)**
   * シークレット追加時、`-s` / `--secret` オプションで渡すか、未指定時は対話形式で安全に入力させる（空入力で安全にキャンセル）。
   * 発行者名は `--issuer` オプションで任意に指定可能とする。
5. **登録データ削除 (`remove` / `rm`)**
   * 指定したサービス名の登録情報を削除する（確認プロンプト、または `-f` / `--force` による即時削除対応）。
6. **設定・解決状態確認 (`config`)**
   * 現在解決されているマスター鍵パス、暗号化ストレージパス、および設定ファイルの解決状態を表示する。

## 4. 非機能要件 (Non-Functional Requirements)

### 4.1 セキュリティ・Zero Leakage Rule（秘密情報の完全防衛）

* **暗号化規格:** AES-256-GCM（認証付き対称暗号）を採用し、改ざん検知と機密性を担保する。
* **標準出力・エラー出力の厳密分離:**
  * `stdout`: 他のコマンドへのパイプ渡し（クリップボード連携等）を安全に行うため、生成された 6 桁コードのみを出力する。
  * `stderr`: 残り有効時間バー（プログレスバー）、進捗状況、対話プロンプト、エラーメッセージを出力する。
* **Zero Leakage:**
  * 通常出力・エラー出力を問わず、平文シークレットや鍵バイト列が画面・ログ・スタックトレースに露出することを厳禁とする。
* **メモリ保護:** 復号された平文シークレットはディスクに永続化せず、必要な処理が終了次第破棄する。

### 4.2 堅牢性・Windows パス入力対策

* **引用符・空白の自動正規化:**
  * Windows エクスプローラーの「パスのコピー」等で混入する前後引用符（`"` や `'`）および空白を自動除去する。
  * 不一致クォート（例: `"path'`）や正規化後に空となるパス（`""`, `'   '`）は引数解析レベルで早期に拒否（終了コード 2）する。
* **未処理例外の抑止:**
  * Windows 特有の不正パス記号（`?` や `*` 等）に起因する `[WinError 123]` や OS エラーを捕捉し、Python のトレースバックを出さずに整形されたメッセージを表示して安全に終了する。
* **明確な終了コード体系:**
  * スクリプト連携時の判定のため、以下の決定的な終了コードを提供する。
    - `0`: 成功
    - `1`: 一般エラー（ファイル I/O 失敗、重複登録等）
    - `2`: CLI 引数解析エラー
    - `3`: 鍵ファイルが存在しない・不正
    - `4`: 暗号化データの破損・復号失敗
    - `5`: 指定サービスが未登録
    - `6`: TOTP シークレット形式不正（Base32 不正等）
    - `7`: ユーザーによるキャンセル

### 4.3 品質・テスト要件

* **カバレッジ:** 単体テストおよび統合テストにより、100% のテストカバレッジを維持する。
* **静的解析:** `flake8`、`mypy --strict`、`black --check` に適合し、警告ゼロを維持する。

## 5. CLI設計・コマンド体系

```powershell
# 1. 初回初期化（対話入力または引数指定）
$ totp init
$ totp init -k "C:\Users\...\Personal Vault\master.key"

# 2. サービス追加 (-s / --secret, -i / --issuer)
$ totp add github
$ totp add aws -s "JBSWY3DPEHPK3PXP" --issuer Amazon

# 3. コード取得 (省略形・明示形・クリップボード連携)
$ totp github
$ totp generate github -k "E:\USB\master.key"
$ totp github | Set-Clipboard

# 4. 一覧表示 (ls エイリアス)
$ totp list
$ totp ls

# 5. 削除 (rm エイリアス, -f / --force)
$ totp remove github
$ totp rm github -f

# 6. 鍵更新
$ totp rekey

# 7. 現在の設定確認
$ totp config
```
